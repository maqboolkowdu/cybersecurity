4.1

Cybersecurity Devices and Technologies

The hardware, software, and habits that form an organization's front line.

4.1.1

Security Appliances

Security appliances can be standalone devices, like a router, or software tools running on a network device. They fall into six general categories:

⇄

Routers

Primarily interconnect network segments, but usually provide basic traffic filtering to control which segments can communicate.

🧱

Firewalls

Look deeper into traffic to block malicious behavior, applying sophisticated security policies to what passes through.

🛡

Intrusion Prevention (IPS)

Uses traffic signatures to match and block malicious traffic and attacks.

🔐

VPN Systems

Let remote employees connect through a secure, encrypted tunnel, and securely interconnect branch offices with headquarters.

🦠

Antimalware / Antivirus

Use signatures or behavioral analysis to identify and block malicious code from executing.

⚙

Other Devices

Web and email security appliances, decryption devices, access control servers, and security management systems.

4.1.3

Firewalls — Types and Purpose

A firewall controls or filters which communications are allowed in and out of a device or network — as a single-computer host-based firewall, or a standalone network-based firewall covering an entire network. As attacks have grown more sophisticated, so have firewall types:

1

Network Layer

Source and destination IP addresses.

2

Transport Layer

Source and destination data ports and connection states.

3

Application Layer

A specific application, program, or service.

4

Context-Aware Layer

User, device, role, application type, and threat profile.

5

Proxy Server

Web content requests such as URLs, domain names, and media types.

6

Reverse Proxy Server

Placed in front of web servers to protect, hide, offload, and distribute access.

7

NAT Firewall

Hides or masquerades the private addresses of network hosts.

8

Host-Based

Ports and system service calls on a single computer's operating system.

4.1.5

Port Scanning

Every application running on a device gets a port number that identifies it to both ends of a transmission. Port scanning probes a computer, server, or host for open ports — useful maliciously as reconnaissance, or harmlessly by an administrator verifying network security policy.

A scan (for example with a tool like Zenmap, pointed at your computer's IP address) will report one of the following responses for each port:

✓

Open / Accepted

Other network devices can access the port or service running on the computer.

✕

Closed / Denied / Not Listening

The port or service isn't running, so it can't be exploited.

⛔

Filtered / Dropped / Blocked

A firewall is blocking access to the port or service.

i
Scanning from outside

To scan from outside your network, you run the scan against your router or firewall's public IP address (search 'what is my IP address?' to find it). If ports like 21, 22, 25, 80, 443, or 3389 come back open, port forwarding is likely enabled and you're running servers on your private network.

4.1.7

Intrusion Detection & Prevention Systems

Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) are security measures deployed on a network to detect and prevent malicious activity.

An IDS can be a dedicated device or a tool within a server, firewall, or host OS that scans traffic against a database of rules or attack signatures. On a match, it logs the detection and alerts an administrator — but takes no action itself, so it doesn't prevent the attack. Because scanning adds latency, an IDS is often placed offline, working from traffic mirrored by a switch.

An IPS goes further — it can block or deny traffic on a positive signature match. Snort is one of the best-known IPS/IDS systems; its commercial version is Cisco's Sourcefire, which performs real-time traffic and port analysis, logging, content matching, probe/attack detection, and port scans, and integrates with third-party reporting and log-analysis tools.

4.1.8

Real-Time Detection

Many organizations can't detect attacks until days or months after they happen. Real-time detection requires actively scanning with firewalls and IDS/IPS devices, next-generation malware detection connected to global threat centers, and context-based behavior analysis. DDoS attacks are especially hard to defend against in real time because they originate from thousands of zombie hosts and look like legitimate traffic.

4.1.8

Advanced Malware Protection (AMP)

One defense against zero-day attacks and APTs is an enterprise-level malware detection solution, such as Cisco's Advanced Malware Protection (AMP) Threat Grid. Deployed on endpoints, as a standalone server, or on other security devices, it analyzes millions of files against hundreds of millions of known malware artifacts, giving multiple teams a global view of attacks:

SOC

Secure Operations Center

Gathers more accurate, actionable data from Threat Grid analysis.

IR

Incidence Response Team

Gains forensically useful information to analyze and understand suspicious behavior faster.

TI

Threat Intelligence Team

Uses the analysis to proactively improve the organization's security infrastructure.

SIE

Security Infrastructure Engineering

Consumes and acts on threat information faster — often in an automated way.

4.1.10

Security Best Practices — Governance

Many national and professional organizations, including NIST's Computer Security Resource Center, publish security best-practice guidelines. Start with the foundations:

✓Perform a risk assessment to know and justify what you're protecting and why
✓Create a security policy outlining rules, job roles, and employee expectations
✓Run human resources security checks, including background checks for all employees
4.1.10

Security Best Practices — Operations

Day-to-day operational habits that keep defenses actually working:

✓Apply physical security measures — restrict access to networking closets and server rooms, and install fire suppression
✓Perform and test backups regularly, including recovery drills
✓Maintain security patches and updates across servers, clients, and network devices
✓Employ access controls with defined user roles, privilege levels, and strong authentication
✓Regularly test incident response with a dedicated team and emergency scenarios
4.1.10

Security Best Practices — Technology & Training

Rounding it out with the tools and awareness that support everything above:

✓Implement a network monitoring, analytics, and management tool that integrates with other technologies
✓Implement modern network security devices — next-generation routers, firewalls, and appliances
✓Implement a comprehensive endpoint security solution with enterprise-level antimalware and antivirus
✓Educate users through security-procedure training (the SANS Institute is a widely respected provider)
✓Encrypt all sensitive organizational data, including email
4.2

Behavior Approach to Cybersecurity

Catching what signatures miss by watching how traffic behaves — and stress-testing your own defenses.

4.2.1

Behavior-Based Security

Behavior-based security captures and analyzes the flow of communication between a user on the local network and a local or remote destination. Any changes to normal behavior patterns are treated as anomalies that may indicate an attack.

🍯

Honeypots

A behavior-based detection tool that lures attackers in by appealing to their predicted malicious patterns. Once inside, an administrator can capture, log, and analyze their behavior to build a better defense.

🛰

Cisco Cyber Threat Defense

A security architecture using behavior-based detection and indicators for greater visibility, context, and control — aiming to answer who, what, where, when, and how an attack is happening.

4.2.2

NetFlow

NetFlow gathers information about data flowing through a network — who and what devices are on it, and when and how users and devices access it. It's an essential component of behavior-based detection: switches, routers, and firewalls equipped with NetFlow report data entering, leaving, and moving through the network. NetFlow collectors then store and analyze that data to establish baseline behavior across more than 90 attributes, such as source and destination IP address.

4.2.3

Penetration Testing — Planning & Scanning

Penetration testing (pen testing) assesses a system, network, or organization for security vulnerabilities by actively trying to breach it — improving defenses against future attacks. It runs through five phases:

1

Planning

Gather as much information as possible about the target — potential vulnerabilities and exploits — through passive or active surveillance (footprinting) and vulnerability research.

2

Scanning

Carry out active reconnaissance: port scanning to find access points, vulnerability scanning to find exploitable weaknesses, and enumeration to identify user, system, and admin accounts.

4.2.3

Penetration Testing — Access & Reporting

1

Gaining Access

Attempt to breach the system using an exploit payload, physical barrier breaches, social engineering, website or software/hardware vulnerabilities, access-control breaches, or cracking weak Wi-Fi encryption.

2

Maintaining Access

Stay inside undetected — typically via backdoors, Trojan horses, rootkits, or other covert channels — while gathering valuable data.

3

Analysis & Reporting

Deliver a report recommending product updates, policy changes, and training to improve the organization's security.

4.2.5

Impact Reduction

No security practice is foolproof, so organizations must be ready to contain damage quickly if a breach occurs.

✓Communicate the issue — internally to employees with a clear call to action, and externally to clients through direct communication and official announcements
✓Be sincere and accountable — respond honestly and take responsibility where the organization is at fault
✓Provide the details — explain why the breach occurred and what was compromised; typically cover client costs for related identity theft services
✓Find the cause — bring in forensics experts if needed to fully understand what happened
✓Apply lessons learned — make sure forensic findings actually change future practice
✓Check, and check again — attackers often leave a backdoor for future access, so verify systems are genuinely clean
✓Educate — raise awareness and train employees, partners, and clients to prevent future breaches
4.2.6

What Is Risk Management?

Risk management is the formal process of continuously identifying and assessing risk to reduce the impact of threats and vulnerabilities. You cannot eliminate risk — only determine acceptable levels by weighing a threat's impact against the cost of mitigating it. As a rule, the cost of protection should never exceed the value of the asset being protected.

1

Frame the Risk

Identify threats that increase risk — processes, products, attacks, service disruption, reputational damage, legal liability, or loss of intellectual property.

2

Assess the Risk

Determine how severe each threat is, prioritizing by financial impact (quantitative) or operational effect (qualitative).

3

Respond to the Risk

Develop an action plan detailing where risk can be eliminated, mitigated, transferred, or accepted.

4

Monitor the Risk

Continuously review risk that's been reduced — you can't eliminate all risk, so ongoing monitoring is essential.

4.3

Cisco's Approach to Cybersecurity

A real-world model for incident response, playbooks, and access control at scale.

4.3.1

Cisco's CSIRT

Many large organizations maintain a Computer Security Incident Response Team (CSIRT) to receive, review, and respond to security incident reports. Cisco's CSIRT goes further, offering proactive threat assessment, mitigation planning, incident trend analysis, and security architecture review to prevent incidents before they happen.

Cisco's CSIRT collaborates with the Forum of Incident Response and Security Teams (FIRST), the National Safety Information Exchange (NSIE), the Defense Security Information Exchange (DSIE), and the DNS Operations Analysis and Research Center (DNS-OARC) to stay current with new developments. National and public CSIRT organizations — like the CERT Division at Carnegie Mellon University — help other organizations build and improve their own incident management capabilities.

4.3.2

The Security Playbook — Core Guidance

One of the best ways to prepare for a security breach is to prevent it. A security playbook is a collection of repeatable queries and reports outlining a standardized incident detection and response process, and it should be built around this guidance:

✓How to identify cybersecurity risk to systems, assets, data, and capabilities
✓Implementation of safeguards and personnel training
✓A flexible response plan that minimizes impact and damage during a breach
✓Security measures and processes to apply in the aftermath of a breach
4.3.2

The Security Playbook — What Else It Should Do

Beyond the core guidance, an effective playbook should also:

✓Highlight how to identify and automate responses to common threats — malware-infected machines, suspicious activity, or irregular authentication attempts
✓Describe and clearly define inbound and outbound traffic
✓Provide summary information, including trends, statistics, and counts
✓Provide fast access to key statistics and metrics
✓Correlate events across all relevant data sources
4.3.3

Tools for Incident Detection and Prevention

SIEM

Security Information & Event Management

Collects and analyzes security alerts, logs, and other real-time and historical data from network security devices to enable early attack detection.

DLP

Data Loss Prevention

Stops sensitive data from being stolen or escaping the network, monitoring data in use, in motion, and at rest.

4.3.4

Cisco's ISE and TrustSec

Cisco Identity Services Engine (ISE) and TrustSec enforce user access to network resources by creating role-based access control policies — ensuring the right people and devices get exactly the access they need, and nothing more.
